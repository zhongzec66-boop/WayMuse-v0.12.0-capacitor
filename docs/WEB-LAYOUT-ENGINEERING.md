## 一、设计稿的四列结构

从 `index.html` 读到（`.app { grid-template-columns: 66px minmax(240px,27%) minmax(400px,1fr) 68px }`）：

| 列 | 宽度 | 内容 | 现状对应 |
| --- | --- | --- | --- |
| 1 | 66px | Agent 身份 + 群聊窄栏 + 添加 | **没有对应物**：现在只有一个 App 身份，没有多 agent/群概念 |
| 2 上 | 27% | **今日计划与课程摘要**：今日三件 + 下节课（不放空间导航） | `todayTop3` 的选取结果 + 下节课计算（已有纯函数） |
| 2 下 | 27% | **会话索引**：聊天列表 + 新建 | **没有对应物**：现在只有单条会话流，列表先只显示当前一条 |
| 3 | 1fr | 主聊天区（气泡、建议卡、确认按钮） | `ChatPage`（1396 行）+ `BriefCard`/`DeadlineCards` |
| 4 | 68px | 右侧竖向胶囊 Tab —— **唯一的空间切换器** | `WebDock` 底部 Tab 的竖排变体（`WayMuseReference` 的 `Page` 路由） |

**结论**：列 2 上、列 3、列 4 都能从现有代码映射；**列 1 和列 2 下是全新概念**（多 agent、多会话），不是布局问题，是数据模型问题。

## 二、组件边界（建议）

```
<AppShell>                       新增：四列 grid + 断点 + 窄屏折叠
  <AgentRail/>                   新增：66px，本机只有一个身份就先渲染 WayMuse +「+」
  <SpacePanel>                   新增：27% 上半
     <TodayDigest/>              新增：今日三件 + 下节课摘要（复用 todayTop3，不新增导航）
     <ThreadList/>               新增：会话索引 + 新建（多会话落地前只显示当前一条，不做假列表）
  <ThreadPanel>                  复用 ChatPage，去掉自身外框
  <ToolRail/>                    新增：右侧 68px 竖排 Tab，取代 WebDock 的横排
</AppShell>
```

原则：**外壳新增、页面不改**。

**不要在第 2 列恢复「主要聊天 / 今天 / 计划 / 记忆」这组空间导航**——空间切换只走右侧 Tab，两处并存会立刻出现"哪套高亮为准"的问题。`ChatPage` / `TodayPage` / `TaskPage` / `MemoryPage` 作为内容组件挂进槽位，第一步不动它们内部。

## 三补、原型侧已修的三处（迁移前要确认仍然成立）

按 Denise seq 94 指出、Codex seq 95 已修：

1. **切 Tab 只换标题、正文不切换** → 原型已改为整块正文切换；迁到 React 时验收标准是"点 Tab 后第 3 列整块换页"，不是换标题。
2. **右栏「聊天」入口重复**（星形按钮、返回箭头、胶囊 Tab 三处）→ 原型已收敛为：顶部只留「新建对话」，导航只留胶囊 Tab，返回箭头仅在有层级时出现。
3. **群聊混在个人会话列表里** → 原型已把群聊移到最左列，个人列表只剩会话。

迁移时必须逐条复验，任何一条回退，说明实现走了捷径。

## 四、三个主要工程问题

### 问题 1：列 2 下（聊天列表）与列 1（群聊）不是布局问题，是数据模型问题

现在 `storage` 里只有一条消息流（`getDeepSeekMessages`），`ChatPage` 直接读写它。
要做列表，先要 `conversations: { id, title, updatedAt, messages }` 与「当前会话」指针；否则列表只有一个条目，等于假功能。

### 问题 2：`WayMuseReference` 是巨型顶层组件，再加四列会继续膨胀

它已经 521 行，装着路由、Dock、备份、引导、课程导入。建议 P1 时把「外壳」抽成 `AppShell`，`WayMuseReference` 只保留状态与路由注入。

### 问题 3：右栏 Tab 与现有 `WebDock` 是两套导航

同一批页面出现两套入口（底部横排 + 右侧竖排）。必须定死：**网页版用右栏、窄屏用底部**，同一份 `Page` 状态驱动，不能各自维护高亮。

## 五、最先落地的一步（建议 P1，约 1 天）

只做外壳，不动任何业务：

1. 新增 `src/shell/AppShell.tsx` + `src/styles/shell.css`：四列 grid、CSS 玻璃、三档断点；
2. 新增 `src/shell/ToolRail.tsx`：右栏竖排 4 个图标，点击切换 `Page`；
3. `WayMuseReference` 渲染 `<AppShell>`，把现有页面塞进槽位；
4. 断点：`≥1200px` 四列；`768–1199` 三列（隐藏列 1）；`<768` 保持现有单列（手机不变）。

验收：三档宽度截图 + 手机宽度无回退 + `tsc`/`lint`/`build`/202 tests 全过。

## 七、迁回 React 的最小任务清单（原型 → 正式产品）

原型能点不等于产品可用。按「先能切换、再能存取、最后能同步」排：

| # | 任务 | 依赖 | 验收 |

| 1 | `AppShell` 四列 grid + `ToolRail` 右栏 | 无 | 三档宽度截图；手机宽度无回退 |
| 2 | `Page` 状态上提，Tab 点击后列 3 整块换页 | 1 | 四张截图：聊天/Today/计划/记忆 |
| 3 | `TodayDigest` 复用 `todayTop3` + 下节课 | 2 | 与 Today 页数字一致 |
| 4 | 会话索引：先单条真数据（不做假列表） | 2 | 刷新后仍在 |

| 6 | 左栏任务勾选写同一份任务数据 | 3 | 勾选后 Today 进度同步 |
