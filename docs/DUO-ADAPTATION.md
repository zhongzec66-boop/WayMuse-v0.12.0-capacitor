# iPhone Duo 风格 + 折叠屏适配方案

> **范围（2026-11-16 收敛）**：本期只做 **Duo 视觉形态**——顶部工具 + 竖排胶囊 Tab 的手机适配。
> 折叠/双屏的双栏适配**不在本期**，正文第三节保留为后续设计参考，不排期、不实现。
>
> 依据：chez「安卓折叠先不做，就是要适配 iPhone Duo」。
> 本文给方案与冲突点，不含代码改动。

---

## 一、先界定两种形态

| 形态 | 指什么 | 影响 |
| --- | --- | --- |
| A. Duo 视觉（手机） | 顶部右角独立工具按钮 + **竖向胶囊 Tab**，取代现在的底部横排 | 与 iOS 原生 Tab 栏直接冲突 |
| B. 折叠/双屏（设备能力） | 展开时左右分栏、折叠时单栏；处理铰链、安全区、窗口尺寸变化 | 需要平台能力判断，Web 与原生不一样 |

---

## 二、断点矩阵（建议）

| 宽度 | 布局 | 导航形态 |
| --- | --- | --- |
| `< 600`（手机竖屏） | 单栏内容 | **右下角悬浮竖向胶囊**（不是贴右边缘） |
| `600–899`（折叠展开窄、小平板竖屏） | 内容 + 底部胶囊或右栏二选一 | 以内容宽度为准，优先单栏 |
| `900–1199`（折叠展开、iPad 竖屏） | 两栏：内容 + 会话/摘要侧栏 | 右栏竖向 Tab |
| `≥ 1200`（桌面、iPad 横屏） | 四列（与网页版一致） | 右栏竖向 Tab |

**关键修正**：手机上不要做成"贴最右侧整条竖向 Tab"。手机单手拇指够不到顶部右侧与右边缘，Duo 的竖向胶囊在折叠机上成立，在 6.1 寸手机上会变成负担。建议：**右下角悬浮短胶囊（3–4 个图标，垂直排列，随内容滚动隐藏/展开）**，视觉接近 Duo，但可达性成立。

## 三、折叠/双屏怎么判断（附录，不在本期范围）

| 平台 | 手段 | 现状 |
| --- | --- | --- |
| Android 折叠（Chromium WebView） | CSS `env(viewport-segment-*)` 环境变量，可拿到铰链位置 | 可用，但需真机验证；WebView 版本影响支持度 |
| Android 原生 | `WindowManager` 的 `FoldingFeature`（需写 Java 插件） | **未实现**，要新增插件 |
| iOS / iPadOS | 没有 CSS 分段能力；用窗口尺寸 + 横竖 + 多任务宽度判断 | 无需插件，但只能按宽度近似 |
| Windows 双屏 | 按窗口宽度处理 | 与桌面一致 |

结论：**Web 层先用宽度 + 安全区做近似**；精确铰链判断只在 Android 上值得做，且需要一个新插件（本轮不做）。

---

## 四、最大的冲突：原生 Tab 栏

现在 iOS 上是**原生 Tab 栏 + 原生输入框**（`patches/liquid-glass`），画在 WebView 之上。要做 Duo 风格的竖向胶囊，只有两条路：

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| A. 手机端关掉原生 Tab，全用 Web 胶囊 | 常态 `useHideNativeChrome`，导航改 Web 实现 | 失去原生玻璃质感与最小化能力；原生输入框可保留 |
| B. 保留原生 Tab，只在网页版（iPad/桌面）用竖向胶囊 | 手机维持现状 | 手机端不是 Duo 风格，与 chez 要求不符 |

**必须选一个。** 我倾向 A 的改良版：**保留原生输入框，导航换成 Web 竖向胶囊**，因为导航是纯视觉，输入框才是体验关键。

## 五、分阶段（每步可回滚）

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| D1 | 手机端竖向胶囊（右下悬浮）+ 顶部右角工具按钮；原生 Tab 常态化隐藏 | 手机截图 3 张（聊天/Today/计划）+ 单手可达性说明；返回手势正常 |
| D2 | 折叠展开双栏（按宽度近似） | 600/900/1200 三档截图；旋转不断裂 |
| D3 | Android 铰链精确判断（新插件） | 真机折叠/展开录屏 + 断点切换日志 |
| D4 | 与网页版四列统一 | 一套断点，不出现两套导航 |

---

## 六、需要拍板的三个问题

1. **手机端是否放弃原生 Tab 栏**（方案 A）？这是 D1 的前提。
2. 竖向胶囊放**右下悬浮**（我推荐）还是贴右边缘通栏？
3. 折叠适配先做**宽度近似**（本周可上），还是等 Android 铰链插件连同真机一起做？
